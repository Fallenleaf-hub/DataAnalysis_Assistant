# Data Analysis Assistant 项目约束与设计红线规范

> **规范目的**：本规范作为 DataAnalysis_Assistant 项目的最高技术纪律与架构红线准则，所有 AI 智能体、开发人员在编写代码、设计界面、优化算法及组织架构时，**必须严格无条件遵守**。

---

## 一、 工作区整洁与临时产物隔离纪律 (Workspace Hygiene & Scratch Isolation)

1. **严禁污染工作区根目录**：
   - 严禁在当前工作区的根目录下直接创建、写入或生成任何临时测试脚本（如 `test_*.py`、`tmp_*.py`、`inspect_*.py`、`check_*.py` 等）；
   - 严禁在工作区根目录下直接倾倒任何中间排版产物、过程调试数据、日志导出、临时测试截图或检验成果文件（如 `dump.json`、`*.tmp`、`*.bak`、`temp_*.png` 等）。
2. **强制使用专属临时目录（scratch/）集中收容**：
   - 在思考、推理、演算、代码调试或阶段性检验过程中产生的所有临时脚本、测试代码、过程数据及检验成果，**必须统一、强制存放在当前工作区根目录下的 `scratch/` 目录**（若不存在则自动创建）；
   - 任何命令行调用、文件生成或工具读写，必须显式指定该专用目录路径（例如：编写 `scratch/test_calc.py`、执行 `python scratch/test_calc.py`、输出缓存至 `scratch/output.json` 等），严禁在根目录随手落地文件。
3. **正式交付物与过程文件严格分离**：
   - 只有经过最终验证、确认作为项目正式组成部分的核心源码、最终文档、正式研报或资产，方可整理移入工作区的正规工程目录；
   - 任务完成后，工作区根目录必须始终保持清爽、整洁、规范，只保留项目正式核心文件，绝不残留任何临时脚本与过程废弃物。

## 二、 UI 视觉风格与纯文本零 Emoji 红线 (Zero Emoji / Pure Text Discipline)

1. **按钮与指示控件 Emoji 绝对禁止红线**：
   - 放大查看器弹窗、数据可视化大屏操作栏、设置二级面板、对话气泡操作栏以及全局所有功能按钮中，**严禁携带任何装饰性 Emoji 或字符图标**（如 `🔍 放大`、`🔍 100%`、`📋 复制`、`💾 另存为`、`🗖 全屏`、`✕ 关闭` 等）；
   - 一律采用克制、现代、高质感的**纯文本标签**（如 `100%`、`复制`、`另存为`、`全屏`、`还原`、`关闭`、`在资源管理器中打开`、`重新检测 Python 环境`、`导入技能...` 等）；
   - 缩放比例指示器仅展示纯数字与百分号（如 `100%`、`125%`），禁止添加任何图标前缀或后缀。
2. **项目约束已固化**：
   - 此规范已写入项目核心约束体系，后续所有新增或修改的界面按钮一律严格执行，杜绝回退。

## 三、 窗口拉伸与大图适屏交互红线 (Window Resizing & Viewport Red Line)

1. **边角拉手纯透明原生光标规范**：
   - 放大查看器界面本身**不得渲染任何可见文字、方块或图标抓手**；
   - 左右两侧底角必须布置 `36×36` 像素的纯透明感应热区（`Background="Transparent"`）；
   - 鼠标移入热区时，由 WinUI 3 `ProtectedCursor` 机制直接呈现 Windows 原生拉伸光标：
     - **右下角**：`InputSystemCursorShape.SizeNorthwestSoutheast`（$\nwsearrow$）
     - **左下角**：`InputSystemCursorShape.SizeNortheastSouthwest`（$\ne-sw$）
   - **1:1 绝对中心对称跟手拉伸**：采用几何中心对称数学算法（$\text{Width} = 2 \times |\text{MouseX} - \text{CenterX}|$），确保卡片边缘实时精准贴合鼠标指针，消除拖拽迟滞。
2. **每次打开默认全屏沉浸展示与 100% 完整适屏算法 (Fit to Viewport)**：
   - 每次打开放大查看器，窗口**默认以全屏模式沉浸展开**，四周留有自适应呼吸边距，支持一键点击【还原】按钮切换为 $1050 \times 720$ 居中标准卡片；
   - **绝不记忆上次关闭前拉伸调整过的宽高状态**，重新打开始终保持全屏首选态；
   - 结合自适应适屏居中算法（`FitPlotImageToViewport`），首帧必须 100% 完整展示整图全貌，四周留有均匀呼吸内边距，彻底杜绝图表被局部裁剪截断。
3. **顶栏物理分列防穿透与自由平移**：
   - 顶栏双列网格物理隔离，左侧标题与文件路径带 `TextTrimming="CharacterEllipsis"`，杜绝小窗口下文本穿透重叠右侧操作栏；
   - 放大状态下，鼠标在画布呈现 Hand 抓手，支持鼠标左键按住自由平移画布（Pan）。

## 四、 CodeAct 数据保真与计算下推铁律 (Code-to-Data Ground Truth Policy)

1. **计算下推准则：Code-to-Data（数据不动代码动）**：
   - 原始全量数据（即使包含数百万行记录）始终 100% 完整留存于本地磁盘或内存；
   - **严禁直接把原始大表明细硬塞入 Prompt**（杜绝 Token 爆炸与数据截断导致模型靠幻觉口算）；
   - 大模型只负责编写精确的 Python 数据分析代码在本地执行。
2. **元数据优先探查：Schema-First 机制**：
   - 先由 `DataSchemaProfiler` 工具为模型提供字段名、类型、缺失率、极值与前 5 行样例的骨架视图，以极小 Token 换取全局宏观认知。
3. **非结构化文档高保真按需检索 (Precision Chunking)**：
   - PDF/Word 先解析大纲目录定位章节，按需原文字节级无损提取，严禁二手 AI 摘要或截断。
4. **严格界定上下文压缩边界 (Safe Compaction Boundary)**：
   - 调试代码、报错输出可压缩；
   - **全量代码计算产生的 Ground-Truth Metrics 最终事实统计表、业务文档关键口径原文、任务约束永久常驻上下文，严禁压缩**。
5. **确定性断言与一致性核验**：
   - 研报中的关键数值必须与 Python stdout 中的计算真值正则匹配核验，杜绝数据幻觉。

## 五、 产物捕获与执行隔离红线 (Plot Capture & Execution Sandbox)

1. **Matplotlib 双向全接口 Monkey-Patch Hook**：
   - 代码垫片必须同时拦截过程式 `plt.savefig` 与面向对象 `Figure.savefig`；
   - 统一按照 `原名_时间戳_短UUID.ext` 镜像一份至沙盒目录 `scratch/agent_sandbox/` 并输出标记；
   - 垫片中坚决不重复配置 `Agg`，防止与顶层预处理器冲突，异常信息向 `stderr` 透传。
2. **遗留资产动态扫描回收**：
   - 脚本执行退出后，对比 `scratch/` 根目录增量文件，自动搬运遗留图表至沙盒，确保图表 100% 捕获至前端画廊。
3. **前端渲染防裂图红线**：
   - 严禁在 Markdown 正文中输出形如 `![...](xxx.png)` 的相对路径图片语法；
   - 所有生成图表必须通过系统专属多模态卡片与大屏画廊统一渲染。
4. **防重复出图阻断**：
   - 工具执行成功回填时，注入系统标记：`[ARTIFACT_CONFIRMED]`，强力阻断大模型无意义重复重绘。

## 六、 专属受控用户 Skill 扩展红线 (Specialized Skill Sandbox Boundary)

1. **专属受控根目录锁死**：
   - 技能存储路径严格锁定为 `%APPDATA%\DataAnalysis_Assistant\skills`；
   - 严禁向系统全局目录（如 `~/.gemini`、`~/.claude`、`~/.skills`）进行跨工具探测扫描，保持环境纯净。
2. **受控沙盒边界红线警告**：
   - 提取 `SKILL.md` 规约注入 System Prompt 时，必须显式注入安全边界声明：
     > “【⚠️ 系统受控沙盒环境边界约束】：
     > 当前任务运行在本地专属数据沙盒中。技能指南中引用的内部配置文件与脚本（如 manifest.yaml、static/* 等）属于技能系统元架构，在当前执行环境中物理不可达。
     > 严禁调用 read_document 或编写 Python 代码尝试搜索这些技能内部文件！请直接基于技能指南中的绘图哲学与配色规范对用户数据进行分析。”
   - 彻底根除模型因机械执行指南而陷入沙盒死循环空耗迭代的严重缺陷。

## 七、 调度状态机、超时与时序防竞态红线 (Scheduler State Machine & Concurrency)

1. **取消令牌 (CancellationToken) 绝对最高优先级**：
   - 一旦检测到用户点击【停止】，系统立即跳出主循环，坚决不再发起任何大模型请求，直接标记 `TerminationReason = UserCancelled`。
2. **终轮双状态强制收敛**：
   - 达到最大探索轮次（默认 12 轮，UI 可调 6-20 轮）时，协议层设置 `tool_choice="none"` 并在代码层直接丢弃 `tool_calls`，确保强制输出全量综合研报。
3. **执行分级超时与 heavy_work**：
   - 基准超时放宽至 60s（UI 开放 30s-120s），代码强制施加 `Math.Max(60, ...)` 兼容保底；
   - 大表全量计算支持声明 `heavy_work: boolean` 申请放宽超时。
4. **协议链路 CallId 自动补齐**：
   - 流式响应缺失 `id` 时自动兜底 `call_{guid}`，多轮追问完整重建 `assistant(tool_calls)` 与 `tool` 回合。
5. **时序竞态消除**：
   - 后台 Task 线程必须先直接同步为实体完成状态设值，再投递 UI，最后写盘，彻底杜绝持久化为 0 或空。

## 八、 Git 提交与发布控制规范 (Git & Publishing Constraints)

1. **严禁擅自提交与推送**：
   - 严禁未经用户明确指示直接执行 `git commit` 或 `git push` 操作。
2. **过程文件防上传与 .gitignore 锁定**：
   - 所有中间方案草稿文件（如 `*_Target.md`、`*Target*.md`）严格纳入 `.gitignore` 忽略清单，保证不向远程仓库推送任何非核心临时规划文件。
